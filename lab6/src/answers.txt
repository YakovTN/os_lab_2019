1. TCP и TCP/IP
TCP (Transmission Control Protocol) — это протокол транспортного уровня в модели OSI, который обеспечивает надежную,
 ориентированную на соединение передачу данных между двумя узлами сети.
  Он использует механизм подтверждения доставки пакетов и повторной передачи данных в случае потери.

TCP/IP (Transmission Control Protocol/Internet Protocol) — это совокупность протоколов, включающая в себя TCP, 
а также IP (Internet Protocol), который отвечает за маршрутизацию и доставку пакетов в сети.
 В общей структуре TCP/IP используется стек протоколов для управления сетью и передачи данных. 
 Этот стек включает также другие протоколы, такие как UDP, HTTP, FTP, и другие.



 2. TCP vs UDP
TCP:

Ориентирован на соединение.
Обеспечивает надежную передачу данных (с подтверждением и повторной передачей в случае ошибок).
Контролирует порядок доставки пакетов.
Требует большего времени на установление соединения.
Используется для приложений, где важна надежность передачи данных (например, HTTP, FTP).


UDP (User Datagram Protocol):

Не ориентирован на соединение.
Не гарантирует доставку пакетов (нет подтверждения получения).
Нет контроля порядка доставки пакетов.
Быстрее, чем TCP, так как не требует установления соединения.
Используется для приложений, где важна скорость, а не надежность (например, потоковое видео, DNS, VoIP).



3. Системный вызов socket
Системный вызов socket используется для создания нового сокета, который является точкой доступа для сетевой связи.

Он принимает несколько параметров:

Семейство адресов (например, AF_INET для IPv4).
Тип сокета (например, SOCK_STREAM для TCP).
Протокол (обычно 0, если используется стандартный протокол для типа сокета).

Пример на C:
int sockfd = socket(AF_INET, SOCK_STREAM, 0);



4. Системный вызов bind
Системный вызов bind используется для привязки сокета к локальному адресу и порту. 
Это необходимо для серверных приложений, чтобы указать, на каком порту они будут ожидать входящих соединений.

Пример на C:
bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));


5. Системный вызов listen
Системный вызов listen используется на серверной стороне для подготовки сокета к принятию входящих соединений.
 Он указывает операционной системе, что сокет будет использоваться для прослушивания входящих соединений.

Пример на C:
listen(sockfd, backlog);
где backlog — это количество соединений, которые могут быть поставлены в очередь на обработку, если сервер не успевает их принимать.


6. Системный вызов accept
Системный вызов accept используется сервером для принятия входящего соединения. 
Этот вызов блокирует выполнение, пока не будет получено новое соединение.
Он возвращает новый сокет, который используется для взаимодействия с клиентом.

Пример на C:
int newsockfd = accept(sockfd, (struct sockaddr *)&client_addr, &client_len);



7. Системный вызов recv
Системный вызов recv используется для получения данных от удаленного узла через сокет. 
Он позволяет принимать данные в буфер и может блокировать выполнение программы, пока данные не будут получены.

Пример на C:
ssize_t n = recv(sockfd, buffer, sizeof(buffer), 0);



8. Системный вызов send
Системный вызов send используется для отправки данных на удаленный узел через сокет.
Он отправляет данные в буфер, указанный в параметре, на удаленный адрес.

Пример на C:
ssize_t n = send(sockfd, buffer, sizeof(buffer), 0);



9. Системный вызов close
Системный вызов close используется для закрытия сокета и освобождения всех ресурсов, связанных с ним. 
После вызова close сокет больше не может быть использован для передачи данных.

Пример на C:
close(sockfd);



10. Системный вызов connect
Системный вызов connect используется на клиентской стороне для установления соединения с удаленным сервером.
Он инициирует попытку установить TCP-соединение с указанным адресом и портом.

Пример на C:
connect(sockfd, (struct sockaddr *)&server_addr, sizeof(server_addr));
